# Domain Docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs
under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs relevant to the area you're working in. If
either is absent, proceed silently. `/domain-modeling`, reached via
`/grill-with-docs` and `/improve-codebase-architecture`, creates these docs
when a term or decision is settled.

## Use glossary terms

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a term is missing, check whether the project already uses a different
term. Note genuine gaps for `/domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an ADR, cite it and explain why the decision is
worth reopening.
